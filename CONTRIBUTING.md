# Участие в разработке

Спасибо за интерес к Content Factory. Здесь описаны правила подготовки
изменений и проверки перед отправкой.

## О проекте

Content Factory — локальное приложение, которое:

- собирает публикации из Telegram-каналов-источников;
- переписывает текст с помощью локальной модели или облачного AI API;
- направляет публикации в целевые каналы по категориям;
- предоставляет очередь ручной публикации и журнал событий.

База данных, сессия Telegram и рабочие файлы хранятся на компьютере
пользователя. Секреты могут задаваться через `.env` или храниться в базе
в зашифрованном виде. При использовании облачного AI текст передаётся
выбранному поставщику, а опубликованные сообщения и медиа отправляются
в Telegram.

## Правила Pull Request

- **Одна задача — один PR.** Не смешивайте несвязанные изменения.
- **Добавляйте тесты.** Новое поведение должно быть покрыто проверками;
  исключения предварительно обсуждаются в Issue.
- **Перед отправкой выполните локальные проверки:**

  ```powershell
  python -m pytest -q tests
  python tools/check_frontend.py
  python tools/doctor.py
  python tests/check_for_secrets.py
  ```

- **Не коммитьте рабочие данные и артефакты сборки:** `.env`,
  `bot_storage.db`, файлы сессий Telegram, `.venv/`, `build/`, `dist/`,
  `release/`, `temp_media/` и `queue_media/`. Полный список исключений
  указан в `.gitignore` и проверяется скриптом `tests/check_for_secrets.py`.
- **Не добавляйте зависимости без необходимости.** Каждая зависимость
  расширяет поверхность атаки и усложняет сборку приложения.
- **Отправляйте изменения через Pull Request.** Перед слиянием дождитесь
  успешного завершения обязательных проверок CI.
- **Согласовывайте изменения API-контрактов.** Имена полей, маршруты и
  обработчики панели являются частью её публичного интерфейса.

## Структура проекта

```text
main.py            основной цикл парсера и публикация
Site.py            веб-панель и API
database.py        SQLite: схема, миграции, шифрование секретов
secrets_store.py   шифрование через Windows DPAPI
config.py          настройки и пути
admin.html         самодостаточная панель управления
tests/             автоматические проверки
tools/             сборка, самопроверка и проверки панели
```

## Стиль кода

- Python 3.11+; по возможности используйте стандартную библиотеку.
- Пользовательские тексты и поясняющие комментарии пишите на русском языке.
- Имена переменных, функций и модулей задавайте на английском языке.
- Добавляйте миграции схемы в `database.py` с новым номером версии.
  Номера уже существующих миграций не меняйте.

## Вопросы

Если требуются разъяснения, создайте Issue. Крупные изменения лучше
обсудить до начала реализации.
