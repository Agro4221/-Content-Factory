# Участие в разработке

Content Factory собирает публикации из Telegram, подготавливает текст с помощью локальной модели или облачного AI API и направляет посты в целевые каналы. Здесь описаны правила подготовки изменений.

## Перед отправкой изменений

- Разделяйте независимые изменения на отдельные pull request.
- Добавляйте или обновляйте тесты для изменённого поведения.
- Перед отправкой выполните основные проверки:

  ```powershell
  python -m pytest -q tests
  python -m ruff check .
  python -m mypy
  python tools/check_frontend.py
  python tests/check_for_secrets.py
  ```

- Не добавляйте рабочие данные и артефакты сборки: `.env`, `bot_storage.db`, файлы сессии Telegram, каталоги виртуального окружения, `build/`, `dist/`, `release/`, `temp_media/` и `queue_media/`.
- Не добавляйте зависимости без необходимости. Обоснуйте новые пакеты в описании pull request.
- При изменении настроек, схемы базы данных или API обновляйте соответствующие тесты и документацию.
- В описании pull request укажите назначение изменения, заметные для пользователя последствия и выполненные проверки.

## Соглашения по коду

- Python 3.11 или новее.
- Имена модулей, функций и переменных — на английском языке; сообщения интерфейса и пользовательские инструкции — на русском.
- Миграции базы данных добавляются в `database.py` с новым номером версии. Номера существующих миграций не меняются.
- Секреты, файлы сессий, локальные базы данных и собранные артефакты не добавляются в коммиты.

## Структура проекта

```text
main.py            парсер, обработка и публикация постов
Site.py            веб-панель и API
admin.html         интерфейс панели управления
database.py        SQLite, схема и миграции
secrets_store.py   работа с системным хранилищем секретов
routing.py         маршрутизация публикаций по тегам
config.py          настройки приложения и пути
tests/             автоматические проверки
tools/             проверки, сборка и диагностика
```

## Вопросы и предложения

Для обсуждения ошибок и предложений используйте GitHub Issues. Для крупных изменений сначала опишите ожидаемое поведение и затрагиваемые части приложения.
