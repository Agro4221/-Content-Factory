# Как Contributing

Спасибо, что хотите помочь. Коротко о том, как устроена работа в этом проекте.

## Что это за проект

Content Factory — локальное приложение, которое:

- забирает посты из Telegram-каналов-доноров;
- переписывает их через AI (локальная модель или облачный API);
- маршрутизирует по категориям в целевые каналы;
- ведёт журнал событий и очередь ручной публикации.

Всё работает на машине пользователя: база, секреты и медиафайлы не уходят
на сервер. Кода лицензирования и оплаты в проекте нет.

## Правила Pull Request

- **Одна правка — один PR.** Не смешивайте рефакторинг с исправлением.
- **Пишите тест.** Новое поведение без теста не принимается. Исключения
  обсуждаются заранее в Issue.
- **Проверьте локально** перед отправкой:

  ```powershell
  python -m pytest -q tests
  python tools/check_frontend.py
  python tools/doctor.py
  python tests/check_for_secrets.py
  ```

- **Не коммитьте** рабочие данные и сгенерированные файлы: `.env`,
  `bot_storage.db`, `session_name.session`, `.venv/`, `build/`, `dist/`,
  `release/`, `temp_media/`, `queue_media/`, `*.session`.
  Список запрещённых файлов — в `.gitignore` и в `tests/check_for_secrets.py`.
- **Не добавляйте зависимость без нужды.** Новый пакет — это дополнительная
  поверхность атаки и лишняя работа при сборке `.exe`.
- **CI должен быть зелёным.** Прямой пуш в `main` запрещён правилом
  репозитория: изменения идут только через PR.
- **Не меняйте API-контракты** без обсуждения. Имена полей, маршруты и
  обработчики — публичный интерфейс панели.

## Структура

```text
main.py            цикл парсера и публикация
Site.py            веб-панель и API
database.py        SQLite: схема, миграции, шифрование секретов
secrets_store.py   шифрование через Windows DPAPI
config.py          настройки и пути
admin.html         панель управления (один самодостаточный файл)
tests/             автоматические проверки
tools/             служебные скрипты: сборка, самопроверка, проверка панели
```

## Стиль кода

- Python 3.11+, без внешних зависимостей там, где можно обойтись
  стандартной библиотекой.
- Комментарии и тексты в интерфейсе — на русском.
- Имена переменных и функций — на английском.
- Миграции схемы добавляются в `database.py` с новым номером версии;
  номера существующих миграций не меняются.

## Вопросы

Если что-то непонятно — заведите Issue. Там же обсуждаются крупные
изменения до начала работы.
