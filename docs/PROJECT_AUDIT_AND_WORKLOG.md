- Валидация конфигурации Telegram, AI, маршрутизации тем и прокси; некорректные активные настройки отклоняются, вместо незаметного перехода к небезопасному режиму.

- Защита панели Basic Auth при заданных учётных данных; внешний bind без настроенной пары логин/пароль блокируется, удалённый HTTP-доступ запрещается.
- Исправления Windows startup/кодировки, ресурсов PyInstaller и проверки запуска EXE.
- CI для регрессионных тестов, проверки JavaScript, политики ошибок AI, сборки Windows EXE и smoke-test API/HTML/favicon.
- Release workflow для версии по тегу, с проверками, сборкой EXE и SHA-256 checksum.

## 3. Повторный аудит и изменения в этой ветке

Проведён обзор дерева всех 104 отслеживаемых файлов, workflows, зависимостей и тестов; ключевые пути риска анализировались на уровне кода в `main.py`, `Site.py`, `database.py`, `config.py`, `proxy_check.py`, `deps.py`, `env_loader.py`, `startup.py`, `Auth.py`, `integrations/register.py`, `Parser.spec`, HTML/JS-активах. Это широкий статический аудит, а не формальное доказательство отсутствия ошибок во всех возможных исполнениях.

### Исправления, подготовленные в PR #80 и включённые в `main`

1. **Внешний AI endpoint по обычному HTTP.** Ранее настройка `remote_url` разрешала HTTP для любого хоста. При заданном `remote_api_key` это позволяло отправлять Bearer-токен по незашифрованному соединению. Теперь HTTP разрешён только для `localhost`/loopback-адресов; для внешнего endpoint требуется HTTPS. Ограничение поставлено и в панели настроек, и в runtime-валидации.
2. **Повреждённые числовые переменные окружения.** Прямые `int()`/`float()` во время импорта `config.py` могли остановить запуск из-за опечатки в `.env`, выхода значений за диапазон или значений вроде `nan`/`inf`. Добавлены ограниченные парсеры с безопасными значениями по умолчанию для `API_PORT`, задержки открытия браузера и legacy-параметров лицензии, а также проверка `API_LOG_LEVEL`.
3. Добавлен набор регрессионных тестов для новых проверок endpoint URL и переменных окружения.

## 4. Остаточные замечания аудита

- **Хранение настроек и секретов.** Решено: секреты теперь шифруются Windows DPAPI — см. раздел 6. `bot_token`, `tg_api_hash`, `remote_api_key`, `proxy_pass` и `mtproto_key` не лежат в базе открытым текстом и не показываются в панели.
- **Legacy-учётные данные модуля отзывов.** Самописное обратимое XOR/HMAC-обфускация учётных данных, зависящее от HWID/license key, удалена вместе с модулем отзывов (см. раздел 7.4). Такое решение не считалось современным шифрованием с проверкой целостности.
- **Лицензии и оплата.** Legacy-заглушки (`Auth.py`, `startup.py`, `integrations/register.py`) удалены полностью (см. раздел 7.4). Серверной части лицензирования и оплаты в проекте больше нет.
- **Воспроизводимость сборки.** В `requirements.txt` указаны минимальные версии без lock-файла. Поэтому новая сборка в другое время может получить более новые транзитивные зависимости; CI зелёный для конкретного запуска не гарантирует побитово воспроизводимую сборку. Для production-релизов стоит закрепить зависимости.
- **Ограничение end-to-end.** Windows smoke-test использует изолированный runner и проверяет запуск локального API/UI, но не авторизацию реального Telegram-клиента, доступы к целевому каналу или работу настоящего внешнего AI endpoint.

## 6. Безопасное хранение секретов, журнал событий и проверка публикации

### 6.1. Шифрование секретов (Windows DPAPI)

**Было.** `bot_token`, `tg_api_hash`, `remote_api_key`, `proxy_pass`, `mtproto_key`
и `license_key` (на тот момент лицензионные заглушки ещё были в проекте)
передавались в браузер панели в открытом виде.

**Стало.**

- Новый модуль `secrets_store.py` — обёртка над `CryptProtectData` /
  `CryptUnprotectData` (Windows DPAPI) без внешних зависимостей. Значение
  хранится с префиксом `dpapi:v1:`; дополнительная энтропия привязывает блоб
  к приложению, а сам DPAPI — к учётной записи Windows и к машине.
- `database.py` шифрует секретные настройки при записи и расшифровывает при
  чтении. Приложение читает значения как раньше — повторный ввод не нужен.
- **Обратная совместимость.** Значения, сохранённые до включения шифрования,
  читаются как есть. При первом запуске после обновления они автоматически
  переводятся в зашифрованный вид (`migrate_plaintext_secrets`).
- После перезаписи секрета выполняется `VACUUM`: SQLite не обнуляет
  освобождённые страницы, и без пересборки файла открытый текст остался бы
  в неиспользуемых страницах.
- **Панель не показывает секреты.** `GET /api/settings` возвращает маску
  `••••••••` вместо значения. Пустое поле при сохранении означает «оставить
  сохранённое значение», отдельная кнопка удаляет секрет.
- Значения секретов не попадают в журнал, терминал и отчёты. При неудачной
  расшифровке (база перенесена на другой ПК или другой пользователь Windows)
  в журнал пишется факт проблемы без значения, а в панели поле очищается —
  секрет нужно ввести заново.
- **Ограничение.** DPAPI доступен только в Windows. На других платформах
  приложение продолжает работать, но секреты остаются в базе открытым
  текстом; это поведение фиксируется в журнале. Перенос базы на другой
  компьютер делает секреты нечитаемыми — это ожидаемое свойство DPAPI.

### 6.2. Журнал событий

Кнопка «Очистить» очищала только отображение, а записи оставались в базе.
Теперь удаление настоящее: добавлен защищённый эндпоинт
`POST /api/logs/clear`, который требует явного подтверждения (`confirm: true`)
и возвращает количество удалённых записей. Кнопка в панели сначала
запрашивает подтверждение и показывает, сколько записей удалено.

### 6.3. Проверка пути публикации

Путь «источник → AI-рерайт → маршрутизация по теме → отправка → фиксация
публикации» покрыт тестами `tests/test_publication_path.py`. Вместо Telegram
используется записывающий double, вместо облачного AI поднимается локальный
mock-сервер с OpenAI-совместимым контрактом, поэтому проверяется настоящая
HTTP-логика. Разобраны: успешная публикация с маршрутизацией по теме,
запасной канал «общее», водяной знак, ошибки AI (401/403/500/503),
неструктурированный и пустой ответ AI, отсутствие маршрута, повторяемая
ошибка отправки, фильтр рекламы и пустой пост.

## 7. Версия 1.29.0.0: очередь постов, справка, очистка медиа, чистка проекта

### 7.1. Очередь постов

Новая таблица `post_queue` (миграция v8) и раздел «Посты» в панели.
Посты можно править, откладывать, публиковать, отменять и удалять;

между «Автоматически» и «Через очередь».

### 7.2. Справка по кодам журнала

Раздел «Справка» с 35 кодами: что означает запись и что делать.
Расшифровки сверены с кодом, а не написаны «на глаз».

### 7.3. Хранение и очистка медиа

- срок хранения: 1, 2, 3, 7 дней или бессрочно;
- автоочистка просроченных медиа в цикле парсера (раз в 6 часов);
- ручная очистка по сроку и полная очистка — из панели;
- сводка занятости медиа в панели.

### 7.4. Очистка проекта

Удалены заглушки, которые ничего не делали: модуль лицензирования
(`Auth.py`, `integrations/`), страница активации (`activate.html`,
`script.js`, `styles.css`), модуль отзывов с самописной обфускацией
учётных данных и пустой `future_defaults.py`. Номера миграций сохранены,
чтобы уже обновлённые базы оставались валидными.

Убраны из проекта рабочие данные (`.env`, `bot_storage.db`,
`session_name.session`) и сгенерированные каталоги (`build/`, `dist/`,

### 7.6. Известные ограничения

- **Шифрование секретов работает только в Windows** (DPAPI). На других ОС
  секреты хранятся открытым текстом, о чём пишется `WARN-503`.
- **Живая публикация в Telegram не проверена** — нужны настоящие токены.
  Весь контур публикации покрыт тестами на mock-API.
