## 3. Повторный аудит и изменения в этой ветке

Проведён обзор дерева всех 104 отслеживаемых файлов, workflows, зависимостей и тестов; ключевые пути риска анализировались на уровне кода в `main.py`, `Site.py`, `database.py`, `config.py`, `proxy_check.py`, `deps.py`, `env_loader.py`, `startup.py`, `Auth.py`, `integrations/register.py`, `Parser.spec`, HTML/JS-активах. Это широкий статический аудит, а не формальное доказательство отсутствия ошибок во всех возможных исполнениях.

### Исправления, подготовленные в PR #80 и включённые в `main`

1. **Внешний AI endpoint по обычному HTTP.** Ранее настройка `remote_url` разрешала HTTP для любого хоста. При заданном `remote_api_key` это позволяло отправлять Bearer-токен по незашифрованному соединению. Теперь HTTP разрешён только для `localhost`/loopback-адресов; для внешнего endpoint требуется HTTPS. Ограничение поставлено и в панели настроек, и в runtime-валидации.
2. **Повреждённые числовые переменные окружения.** Прямые `int()`/`float()` во время импорта `config.py` могли остановить запуск из-за опечатки в `.env`, выхода значений за диапазон или значений вроде `nan`/`inf`. Добавлены ограниченные парсеры с безопасными значениями по умолчанию для `API_PORT`, задержки открытия браузера и legacy-параметров лицензии, а также проверка `API_LOG_LEVEL`.
3. Добавлен набор регрессионных тестов для новых проверок endpoint URL и переменных окружения.

## 4. Остаточные замечания аудита

- **Хранение настроек и секретов.** Основные значения `bot_token`, `remote_api_key`, `proxy_pass` и `mtproto_key` сохраняются в SQLite как обычные строки. Файл базы исключён из Git, но не зашифрован на уровне приложения. У пользователя должны быть защищены права доступа к каталогу приложения и диск; для более строгой модели безопасности следует спроектировать безопасное хранение ключей.
- **Legacy-учётные данные модуля отзывов.** В `database.py` есть самописное обратимое XOR/HMAC-обфусцирование учётных данных, зависящее от HWID/legacy license key. Это не следует считать стандартным современным шифрованием с проверкой целостности. Модуль отзывов объявлен вне scope локального Content Factory; перед его повторным включением механизм следует заменить на поддерживаемое криптографическое решение с миграцией данных.
- **Лицензии и оплата.** `Auth.py`, `startup.py` и `integrations/register.py` содержат legacy-заглушки: офлайн-статус лицензии может возвращаться как активный, а checkout намеренно отвечает 503. README определяет backend лицензирования и платежей как вне scope локальной версии. Эти endpoints нельзя выдавать за реализованный лицензионный/платёжный сервис.
- **Воспроизводимость сборки.** В `requirements.txt` указаны минимальные версии без lock-файла. Поэтому новая сборка в другое время может получить более новые транзитивные зависимости; CI зелёный для конкретного запуска не гарантирует побитово воспроизводимую сборку. Для production-релизов стоит закрепить зависимости.
- **Ограничение end-to-end.** Windows smoke-test использует изолированный runner и проверяет запуск локального API/UI, но не авторизацию реального Telegram-клиента, доступы к целевому каналу или работу настоящего внешнего AI endpoint.
