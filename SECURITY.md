# Политика безопасности

## Сообщение об уязвимости

Не публикуйте эксплуатационные детали, учётные данные или рабочие токены в публичном Issue. Если для репозитория доступна приватная отправка отчётов об уязвимостях на GitHub, используйте её. В противном случае свяжитесь с владельцем проекта через профиль GitHub.

## Чувствительные данные

Не добавляйте в репозиторий:

- Telegram API Hash и токен бота;
- ключи облачных AI API;
- логины и пароли прокси;
- файлы сессии Telethon (`*.session`);
- личный файл окружения `.env`, базу `bot_storage.db` и резервные копии;
- журналы, содержащие персональные данные или сведения об учётных записях.

В репозитории хранится только шаблон `.env.example`. Перед публикацией изменений выполните проверку:

```powershell
python tests/check_for_secrets.py
```

## Хранение секретов

В целевой Windows-сборке приложение шифрует чувствительные настройки через DPAPI. Зашифрованное значение привязано к учётной записи Windows и компьютеру; копирование базы на другой компьютер не переносит возможность расшифровки. Панель возвращает маску вместо сохранённого секрета и не предназначена для чтения его исходного значения.

Если системное шифрование недоступно, не считайте хранение секретов в локальной базе защищённым. Ограничьте доступ к папке приложения и не передавайте базу или диагностические файлы третьим лицам.

## Панель управления и передача данных

Панель по умолчанию слушает только `127.0.0.1` и не имеет встроенной аутентификации. Не меняйте `API_HOST` на сетевой адрес и не публикуйте порт панели в локальную сеть или Интернет. Защита от запросов чужих сайтов не заменяет аутентификацию.

При использовании облачного AI-провайдера текст публикации отправляется выбранному сервису. Посты и медиа, которые приложение публикует, передаются в Telegram. До включения облачного режима ознакомьтесь с правилами обработки данных соответствующего поставщика.
