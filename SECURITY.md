# Политика безопасности

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости, рабочие учётные данные или готовый сценарий эксплуатации в открытом Issue. Если в репозитории доступна приватная отправка отчётов об уязвимостях, используйте её. В противном случае свяжитесь с владельцем репозитория через GitHub и предоставьте описание проблемы, шаги воспроизведения и возможные последствия.

## Данные, которые нельзя публиковать

Не добавляйте в репозиторий и не передавайте третьим лицам без очистки:

- токен Telegram-бота, Telegram API Hash и ключи облачных AI API;
- пароли и ключи прокси;
- файлы сессии Telethon (`*.session`);
- личный файл `.env`, базу `bot_storage.db` и резервные копии этих файлов;
- журналы или диагностические отчёты, если они содержат личные данные или сведения об аккаунтах.

В репозитории хранится только шаблон `.env.example`. Проверить рабочую копию на случайно добавленные секреты можно командой:

```powershell
python tests/check_for_secrets.py
```

## Панель управления

Панель не имеет встроенной аутентификации. По умолчанию она доступна только через loopback-адрес `127.0.0.1`. Не выставляйте порт панели в локальную сеть или Интернет и не пробрасывайте его через маршрутизатор.

Проверки заголовков Host и Origin дополняют защиту локального API, но не заменяют аутентификацию. Любой пользователь, получивший сетевой доступ к незащищённой панели, потенциально сможет управлять приложением.

## Хранение секретов и передача данных

- В Windows секреты шифруются DPAPI и привязываются к учётной записи пользователя и компьютеру. При переносе базы на другой компьютер их может потребоваться ввести повторно.
- Относитесь к локальной базе данных, файлу окружения и сессии Telegram как к чувствительным данным.
- При выборе облачного AI API текст передаётся выбранному поставщику. Публикации и медиа, отправляемые приложением, передаются в Telegram.
- Не отправляйте базы данных, файлы сессии и диагностические материалы в публичные обсуждения.
